# Community Adapter Lab — Review Checklist

Use this checklist before promoting any public submission.

## A. Privacy / rights

- [ ] No student/person identity remains.
- [ ] No email, phone, signature, student number or private link remains.
- [ ] No diagnosis, clinical report or PDP/Förderplan is reproduced.
- [ ] Material is shareable, or a synthetic/anonymized equivalent is used.
- [ ] Contributor allowed reviewed-example use if promotion is planned.

If any item fails: **do not promote**.

## B. Reproducibility

- [ ] Adapter version is known.
- [ ] Use case is known: STUDY / HOMEWORK / ASSESSMENT.
- [ ] Subject and objective are clear.
- [ ] ASSESSMENT includes assessed competence.
- [ ] Original input and Adapter output are sufficient to reproduce the behavior.

## C. Analysis

Classify with one or more:
- GOOD_EXAMPLE
- ADAPTER_WEAKNESS
- AMBIGUOUS
- ASSESSMENT_SAFETY
- LAYOUT
- LANGUAGE
- OCR_UNREADABLE
- SUBJECT_TERMINOLOGY
- POLICY_CONTEXT
- NEW_USE_CASE
- NO_CHANGE_NEEDED

## D. Improvement decision

Choose one:
- no Adapter change;
- documentation/help improvement;
- example promotion;
- improvement candidate;
- immediate safety review.

If an improvement candidate is created, add it to `IMPROVEMENT_REGISTER.md` and link the source Issue(s).

## E. Promotion

A promoted example must:
- be published as a public-facing page in **German → Italian → English**, in that order;
- receive a `CAE-YYYY-NNN` ID;
- cite its public source Issue;
- use only public-safe content;
- record privacy/rights review status;
- record classification;
- record Adapter version;
- record whether an Adapter change followed.
